# 案例二 · 真机演示现场执行单

> 拓扑：**三机两段**。A 与 C 在二层互不相通，所有帧必须穿过 B 上的 48 星仿真域。
> 版本：2026-11-20　适用配置：`semi_physical/omnetpp-semi-real.ini`

---

## 一、地址与角色

| 机器 | 网卡 | 地址 | 网关 | 跑什么 |
|---|---|---|---|---|
| A 发送 | 唯一网口 | `192.168.100.2/24` | **不配** | `hosts/A`：`bash run_a.sh` |
| B 网卡1 | 板载 | `192.168.100.1/24` | **不配** | 仿真 gatewayA 绑此地址 |
| B 网卡2 | USB/扩展 | `192.168.101.1/24` | **不配** | 仿真 gatewayB 绑此地址 |
| C 接收 | 唯一网口 | `192.168.101.2/24` | **不配** | `hosts/C`：`bash run_c.sh` |

两段网线：`A ── B 网卡1`、`B 网卡2 ── C`。**中间不许接交换机**，否则 A、C 二层连通，帧绕开仿真直达。

## 三、B 的现场配置（10 分钟）

### 1. 两块网卡起地址

```bash
# 先确认网卡名，别照抄 eth1/eth2
ip -br a

sudo ip addr add 192.168.100.1/24 dev <网卡1>
sudo ip addr add 192.168.101.1/24 dev <网卡2>
sudo ip link set <网卡1> up
sudo ip link set <网卡2> up
```

**不要配默认网关**，也不要把默认路由改到这两个网口——否则 B 的互联网流量会灌进实验网段。

### 2. 关掉内核转发（最容易漏，漏了实验就假了）

```bash
sysctl net.ipv4.ip_forward        # 必须返回 0
sudo sysctl -w net.ipv4.ip_forward=0   # 若为 1，立即改回
```

为 1 时，A 的包会被 B 的内核直接转给 C，**根本不过仿真**，但画面上看起来一切正常。

### 3. 端口与防火墙

```bash
sudo ss -lunp | grep -E '5000|5001'   # 必须为空
sudo ufw status                        # 应为 inactive；active 则 sudo ufw disable
```

## 四、起停顺序（严格照此）

| 步 | 在哪 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | B | `cd ~/omnetpp-6.3.0 && source setenv` | 提示符正常 |
| 2 | B | `cd workspace/satnet3d/simulations/education1`<br>`sh ./run -u Cmdenv -f semi_physical/omnetpp-semi-real.ini` | 出现 `2029 modules`；`simsec/sec ≈ 1.000` |
| 3 | A | `ping -c2 192.168.100.1` | 通（B 内核应答） |
| 4 | A | `ping -c2 -W1 192.168.101.2` | **必须不通**（`Network is unreachable` 或 `100% packet loss`） |
| 5 | C | `bash run_c.sh`（Windows 双击 `run_c.bat`） | 窗口弹出，等帧 |
| 6 | A | `bash run_a.sh`（Windows 双击 `run_a.bat`） | C 上画面出现，帧号递增 |
| 7 | B | `sudo tcpdump -i any -n udp and port 5000` | 看到 A→B 与 B→C 两组 1400 B 包 |
| 8 | 全部 | 摆机位、试录 5 s、关无关窗口 | 三窗同框可读 |
| 9 | A | 重新起发送端，正式录 30 s | 帧号从三位数滚到四位数 |

**停止顺序**：先停 A 的发送端 → 再停 B 的仿真（Ctrl+C）→ 最后关 C 的接收端。反了会让 C 挂住等包。

第 4 步是整套演示的**关键证据**：A 无法直达 C，唯一的通路就是仿真域。讲解时一定要现场演示这一次 ping。

## 五、三个必看的证据

1. **A 窗 HUD**：`SENDER 000412` + 时间戳
2. **C 窗 HUD**：`frame 000412 latency xx ms loss 0.0%`
3. 两者**帧号对应、画面连续**

只讲帧号对应，**不要以 C 窗 latency 为准**：三台机器时钟不同步，这个数含 A、C 的钟差，可能漂几十毫秒甚至为负。要报时延，引用 B 上仿真日志里 gateway 的域内统计。

## 六、故障速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 仿真起不来 `Cannot bind real UDP port` | 5000/5001 被上次残留占用 | `sudo pkill opp_run`；`ss -lunp` 复查 |
| C 一直黑屏，B 日志有 `sendto failed` | gatewayB 绑错地址（仍是 127.0.0.1）或网卡2 没插线 | 确认用的是 `omnetpp-semi-real.ini`；查网卡2 状态 |
| A 报 `Network is unreachable` 且第 3 步就失败 | B 网卡1 没起地址 | 回第三节第 1 步 |
| 画面动了但时延是 0.3 ms 级别 | 帧被内核旁路，没过仿真 | 查 `ip_forward`、查两段网线是否接在同一交换机 |
| C 收到帧但花屏、丢帧率高 | 星间链路丢包（正常现象） | 降 `--fps` 到 15、`--quality` 到 55 |
| 仿真 `simsec/sec` 远小于 1 | 机器性能不足，实时调度跟不上 | 关掉其他窗口与浏览器；可降到 8×4 = 32 星 |

## 七、Plan B：真机凑不齐时退回单机

B 上一条命令即可，其余照旧，PPT 上讲“三个角色的逻辑分离”。

```bash
sudo sh ~/omnetpp-6.3.0/workspace/satnet3d/simulations/education1/semi_physical/setup_veth.sh
cd ~/omnetpp-6.3.0/workspace/satnet3d/simulations/education1
sh ./run -u Cmdenv -f semi_physical/omnetpp-semi.ini --sim-time-limit=900s
```

然后 A 用 `--dst 192.168.100.1`、C 用 `--bind 192.168.101.2`，两台都在同一台机上起即可。
2026-11-19 实测：1470 帧、均值 67.9 ms、零丢帧。
