# 案例二 · 真机演示操作卡（三台机器逐条照做）

> 拓扑：**三机两段**。A 与 C 二层不通，所有帧必须穿过 B 上的 48 星仿真域。
> 适用：`A-发送-Windows.zip`（电脑 A）、`C-接收-Windows.zip`（电脑 C）、`B-仿真-Ubuntu.tar.gz`（电脑 B）
> 版本：2026-11-20 晚　实测环境：OMNeT++ 6.3.0 + INET 4.6 + satnet3d

```
 电脑 A (Windows)                电脑 B (Ubuntu)                 电脑 C (Windows)
 192.168.100.2/24   网线①   网卡1 192.168.100.1/24        网卡2 192.168.101.1/24   网线②   192.168.101.2/24
 run_a.bat      ──────────►  gatewayA ──┐            ┌── gatewayB  ◄──────────  run_c.bat
 摄像头 960x540                          ├─ 48 星仿真 ─┤                         弹出视频窗
                                        └────────────┘
                          两台 Windows 机之间没有任何直连通路
```

---

## 0. 每台机器该有什么（对一下，缺了就走不动）

| 机器 | 目录/文件 | 说明 |
|---|---|---|
| A | 解压得到 `A-发送\` | `run_a.bat`、`video_sender.py`、`requirements.txt`、`先看这个-Windows.md` |
| C | 解压得到 `C-接收\` | `run_c.bat`、`video_receiver.py`、`requirements.txt`、`先看这个-Windows.md` |
| B | 解压得到 `education1\` | 必须落在 `~/omnetpp-6.3.0/workspace/satnet3d/simulations/` 下 |

**放错位置是 B 上最常见的失败**：`education1/run` 里写的是 `../../src` 与 `../../../inet4.6/src`，少一层就找不到 `libsatnet3d.so`。放到桌面、家目录都不行。

**克隆来的 git 仓库也不能整个塞进 `simulations/` 下**。`run` 用 `-n ..` 递归扫描 NED，克隆目录里那份 `education1` 会被一起扫到，直接报：

```
Declared package 'satnet3d.simulations.education1' does not match
expected package 'satnet3d.simulations.satnet3d-hil-demo.education1'
```

哪怕 `simulations/education1` 本身是对的，也照样起不来。标准做法：

```bash
git clone <仓库地址> ~/satnet3d-hil-demo     # 克隆放在家目录
cd ~/satnet3d-hil-demo
bash 安装到B.sh                              # 把 education1 装进 simulations/
```

以后更新：`cd ~/satnet3d-hil-demo && git pull && bash 安装到B.sh`。

## 1. 出门前（前一晚做完，别留到现场）

| 机器 | 要做的事 | 验证 |
|---|---|---|
| A | 装 Python 3.9+（**勾 Add python.exe to PATH**） | 命令行 `python --version` 有输出 |
| A | 有摄像头（笔记本自带即可） | 双击 `run_a.bat` 能弹窗、显示 `LIVE 960x540 25fps` |
| C | 同上装 Python | `python --version` |
| C | **入站 UDP 5000 放行**（管理员 cmd）<br>`netsh advfirewall firewall add rule name="UDP5000-in" dir=in action=allow protocol=UDP localport=5000` | `netsh advfirewall firewall show rule name="UDP5000-in"` |
| B | `cd ~/omnetpp-6.3.0 && source setenv && which opp_run` | 打印出 `opp_run` 路径 |
| B | 第二块网卡（USB 千兆）插上，`ip -br a` 能看到两块 | 记住两块网卡名，例如 `enp3s0` / `enx00e04c...` |
| — | 两根网线、摄像头、录像设备、打印本卡 | — |

C 端防火墙**必须提前做**：接收端是被动监听，被防火墙挡住时屏幕上不报错，只是永远黑屏，现场最难查。

## 2. 现场布线（3 分钟）

1. `A ── 网线① ── B 网卡1`
2. `B 网卡2 ── 网线② ── C`
3. **中间不要接交换机/路由器**。一旦 A、C 二层相通，帧会绕开仿真直达，画面照样出，实验就假了。
4. 三台机器先别插外网（B 尤其不要接校园网，避免默认路由把实验流量带走）。

---

## 3. 电脑 B：配地址 + 起仿真（10 分钟，一次配好）

### 3.1 两块网卡起地址

```bash
ip -br a                                   # 先认清哪块是网卡1、哪块是网卡2

sudo ip addr add 192.168.100.1/24 dev <网卡1>
sudo ip addr add 192.168.101.1/24 dev <网卡2>
sudo ip link set <网卡1> up
sudo ip link set <网卡2> up
ip -br a                                   # 复查：两个地址都在
```

**绝对不要给这两块网卡配默认网关**，否则 B 的上网流量会灌进实验网段。

> 如果发现地址过一会儿自己消失（NetworkManager 接管导致），改用持久写法：
> `sudo nmcli con add type ethernet ifname <网卡1> con-name lab1 ipv4.method manual ipv4.addresses 192.168.100.1/24 ipv4.never-default yes`

### 3.2 关掉内核转发（漏了实验就是假的）

```bash
sysctl net.ipv4.ip_forward          # 必须是 0
sudo sysctl -w net.ipv4.ip_forward=0    # 若为 1，立即改回
```

为 1 时，A 的包会被 B 的内核直接转给 C，**根本不过仿真**，画面上却看不出任何异常。

### 3.3 端口与防火墙

```bash
sudo ss -lunp | grep -E ':5000|:5001'    # 必须没有任何输出
sudo ufw status                          # 应为 inactive；active 就 sudo ufw disable
```

### 3.4 起仿真

```bash
cd ~/omnetpp-6.3.0 && source setenv
cd workspace/satnet3d/simulations/education1
sh ./run -u Cmdenv -f semi_physical/omnetpp-semi-real.ini
```

**成功的标志**（实测输出形态）：

```
Setting up network "satnet3d.simulations.education1.SatNet3DEducationSemiPhysicalNetwork"...
Initializing...
Running simulation...
** Event #27392   t=10.871   Elapsed: 10.016s (0m 10s)  90% completed
     Speed:     ev/sec=2734.94   simsec/sec=1.08537   ev/simsec=2519.82
     Messages:  created: 2163   present: 2029   in FES: 59
```

要盯两处：`simsec/sec` 在 **0.95～1.05**（说明实时调度跟得上）、`present: 2029`（48 星网络装齐了）。

**失败的标志**：

```
<!> Error: Cannot bind real UDP port 5000: Cannot assign requested address
```

⇒ 网卡1 的地址没起，或被 NetworkManager 冲掉了，回 3.1。

**不要用 Qtenv**（`-u Qtenv`）：这台机器的 OSG 三维渲染起不来，会卡在 `satellite[47]`。演示一律 Cmdenv。

## 4. 电脑 A：配地址 → 验通路（5 分钟）

### 4.1 配静态 IP

图形：`Win+R` → `ncpa.cpl` → 右键正在用的网卡 → 属性 → `Internet 协议版本 4 (TCP/IPv4)` → 属性 →

- IP 地址 `192.168.100.2`
- 子网掩码 `255.255.255.0`
- **默认网关留空**、DNS 留空

命令行核对：`ipconfig` → 该网卡应为 `192.168.100.2`。

### 4.2 两条 ping（这是整套演示的关键证据，务必当场做）

```cmd
ping -n 2 192.168.100.1
```
应为 **通**（`来自 192.168.100.1 的回复`，因为这时 B 的仿真已经在跑并占用了这个地址）。

```cmd
ping -n 2 -w 1000 192.168.101.2
```
应为 **不通**（`请求超时` 或 `无法访问目标主机`）。

> 这两条 ping 正是讲解的核心：**A 在物理上根本到不了 C**，唯一通路是 B 上的仿真域。
> 若第二条 ping 通了，说明两段网线接在同一台交换机上，或 B 上 `ip_forward=1` —— 停下来查。

## 5. 电脑 C：起接收端（1 分钟）

双击 `C-接收\run_c.bat`（或在解压目录里 `cmd` 执行 `run_c.bat`）。

脚本会先检查 Python、缺库自动 `pip install`，然后启动：

```
C:\...\C-接收> python video_receiver.py --bind 192.168.101.2 --port 5000 --save-csv recv_latency.csv --win-size 1000x560
```

窗口标题 `Receiver`，**先黑屏是正常的**，等 A 开始发。异常提示对照：

| 提示 | 含义 |
|---|---|
| `Cannot assign requested address` | C 的 IP 不是 `192.168.101.2`，回 4.1 |
| 窗口一直黑屏、无报错 | 入站 UDP 5000 被防火墙挡了，或 B 没在跑、或 A 没发 |

---

## 6. 电脑 A：起发送端（1 分钟）

双击 `A-发送\run_a.bat`。实际执行的是：

```
python video_sender.py --src 192.168.100.2 --dst 192.168.100.1 --port 5000 --fps 25 --width 960 --height 540 --win-size 960x540
```

注意 `--dst` 是 **B 的网卡1**（`192.168.100.1`），**不是 C**。写成 C 的地址会直接 `Network is unreachable`。

窗口出现后应看到：

- 左上 `LIVE 960x540 25fps`
- 右上 `FRAME 000001` 递增，旁边是本机时间
- 有 `REC` 标记；`q` 键退出

C 的窗口这时应出现同一画面，左上角叠加：

```
Receiver  frame 412  xx.x KB  delay 68 ms
```

**A、C 两侧帧号要一一对应、画面连续**，这是唯一的硬证据。

## 7. 起停顺序（背下来）

| 序 | 机器 | 动作 |
|---|---|---|
| 1 | B | 配两块网卡地址 → 关 `ip_forward` → 起仿真（第 3 节） |
| 2 | A | 配 `192.168.100.2` → 两条 ping（第 4 节） |
| 3 | C | 双击 `run_c.bat` → 黑屏待收 |
| 4 | A | 双击 `run_a.bat` → C 出画面 |
| 5 | B | （可选）另开终端 `sudo tcpdump -i any -n 'udp and port 5000' -q` 抓包留证 |
| 6 | — | 摆机位、试录 5 s、关掉无关窗口 |
| 7 | A | 关掉重开一次，正式录 30 s，帧号滚到四位数 |

**停止顺序**：先 A 的发送端（按 `q` 或关窗）→ 再 B 的仿真（`Ctrl+C`）→ 最后关 C。
反了会让 C 挂在等包状态。

## 8. 三块屏同框要拍到什么

| 画面 | 要能看清 |
|---|---|
| A 屏 | `FRAME` 编号 + 实时画面 + `LIVE 960x540 25fps` |
| B 屏 | `simsec/sec≈1.0`、`present: 2029`、`satnet3d.simulations.education1...` |
| C 屏 | `Receiver frame N ... delay 68 ms` + 同一画面 |

帧号对得上，就是"经过仿真"的直接证据。**时延数字只作参考**：三台机器时钟不同步，C 上显示的 `delay` 含钟差，可能漂几十毫秒。要报时延，引用之前同机实测的口径（均值 **67.9 ms**，中位 66，P95 68，零丢帧）。

## 9. 讲解三句话（30 秒说完，别展开）

1. "左边这台是**真实摄像头**，画面压成 JPEG、每帧切 1400 字节的 UDP 分片发出去。"
2. "中间这台跑的是 **48 星 Walker 星座**（8 面 × 6 星、1414 km、52° 倾角），包在仿真里经星间链路走到另一侧 —— 不是网线直连。"
3. "右边这台收到分片重组播出，帧号和左边一致。刚才我 ping 过：**A 到 C 是不通的**，通路只有这条仿真链路。"

被追问"怎么证明没作弊"时，展示第 4.2 节那条**不通**的 ping，以及 B 上 `simsec/sec` 和抓包。

## 10. 故障速查（按现象找）

| 现象 | 原因 | 处置 |
|---|---|---|
| B：`Cannot bind real UDP port 5000` | 网卡1 没有该地址 / 被 NM 冲掉 / 上次残留占用 | `ip -br a` 复查地址；`sudo pkill opp_run`；`ss -lunp` 看谁占着 |
| B：`simsec/sec` 只有 0.3～0.6 | 机器性能不足，实时调度跟不上 | 关浏览器与无关程序；降到 8×4=32 星（改 ini 的 `satsPerPlane`） |
| C：一直黑屏、无任何报错 | 入站 UDP 5000 被防火墙挡 / B 没起 / A 没发 | 先看 B 是否在 `Running simulation`，再看 A 窗口是否在走帧 |
| C：黑屏 + B 日志 `sendto failed` | gatewayB 绑的不是 `192.168.101.1`，或网卡2 未插线 | 确认用的是 `omnetpp-semi-real.ini`；`ip -br a` 看网卡2 是否 `UP` |
| A：`Network is unreachable` | A 的 IP 不是 `192.168.100.2`，或 B 网卡1 没起地址 | 回 3.1 / 4.1 |
| A：`OSError: Cannot assign requested address` | A 本机没有 `192.168.100.2` 这个地址 | 同上，`ipconfig` 核对 |
| 画面动了但"时延"只有 0.3 ms 级 | 帧被内核旁路，没过仿真 | 查 `ip_forward`、查两段网线是否同交换机 |
| C 花屏、丢帧 | 星间链路丢包（真实现象） | 降 `--fps 15`、`--quality 55`（在 `run_c.bat` / `run_a.bat` 里加参数） |
| A：`找不到 python` | 装 Python 时没勾 PATH | 重装并勾选，或在 bat 里写全 `python.exe` 路径 |

## 11. Plan B：真机凑不齐时退回单机

B 一台机器演三个角色，PPT 上讲"逻辑分离、物理同机"。

```bash
sudo sh ~/omnetpp-6.3.0/workspace/satnet3d/simulations/education1/semi_physical/setup_veth.sh
cd ~/omnetpp-6.3.0/workspace/satnet3d/simulations/education1
sh ./run -u Cmdenv -f semi_physical/omnetpp-semi.ini --sim-time-limit=900s
```

A、C 两端照旧用 `run_a.bat` / `run_c.bat`，但**把两台都在 B 上起**（或接到 veth 上）。
2026-11-19 同机实测：1470 帧、58.6 s、25 fps、4.97 Mbps、时延均值 67.9 ms、零丢帧。
