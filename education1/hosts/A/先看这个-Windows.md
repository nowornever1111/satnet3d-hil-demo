# 电脑 A（Windows）· 三步启动

> 这台机上只做三件事：**装 Python → 配一个 IP → 双击 `run_a.bat`**。
> 除了第一次装依赖要联网，其余都不需要外网。

## 第 1 步 装 Python（只做一次）

1. 装 Python **3.9 及以上**（python.org 下载页选 "Windows installer"）。
2. 安装界面**务必勾选 `Add python.exe to PATH`**，这一步漏了后面全白搭。
3. 装完开一个 cmd，敲：

   ```
   python --version
   ```

   能打印版本号就成。

## 第 2 步 配 IP

控制面板 → 网络和共享中心 → 更改适配器设置 → 右键那块网卡 → 属性
→ 双击 `Internet 协议版本 4 (TCP/IPv4)` → 使用下面的 IP 地址：

| 项 | 填什么 |
|---|---|
| IP 地址 | `192.168.100.2` |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | **留空** |
| DNS 服务器 | **留空** |

若这块网卡原来还勾着 `Internet 协议版本 6 (TCP/IPv6)`，可以一起取消，减少干扰。

核对：cmd 里 `ipconfig`，那块网卡应显示 `IPv4 地址 . . . : 192.168.100.2`。

## 第 3 步 双击 `run_a.bat`

- 第一次运行会自动 `pip install opencv-python numpy`，之后直接起画面；
- 窗口标题是 `Sender - camera`，里面 `FRAME 000123` 会一直滚；
- Windows 防火墙弹"是否允许 Python 通信"时，**两个勾都打上，点允许**。

窗口里应该看到：

```
本机地址 192.168.100.2   -->   目的 192.168.100.1:5000  （B 网卡1，仿真入口）
```

**目的地址是 B 的网卡1，不是 C。** A 到不了 C 的网段，包只能交给 B 上的仿真域转。

## 开录前的两条自检

在 cmd 里（先 `cd /d` 到本目录）：

```
ping -n 2 192.168.100.1
ping -n 2 -w 1000 192.168.101.2
```

第一条**必须通**；第二条**必须不通**——通了说明 A、C 走同一台交换机绕开了仿真，
这时画面再漂亮实验也是假的。这一条讲解时要当场演示。

## 出问题先看这里

| 现象 | 原因 | 处置 |
|---|---|---|
| 双击黑窗口一闪而过 | 没装 Python 或没进 PATH | 重装并勾 `Add python.exe to PATH` |
| `OSError: [WinError 10049]` | 本机没有 `192.168.100.2` | 回第 2 步 |
| `Network is unreachable` | B 网卡1 没起地址，或网线没插 | 去 B 上 `ip -br a` 看 |
| 画面在 A 上正常，C 全黑 | B 没跑仿真，或 B 用了单机版 ini | B 上用 `omnetpp-semi-real.ini` |
| C 上时延只有 0.x ms | 包被 B 的内核旁路，没过仿真 | B 上 `sysctl net.ipv4.ip_forward` 必须为 0 |
| 摄像头打不开 | 序号不对，或被微信/钉钉/相机占用 | 关掉占用程序；`python video_sender.py --list-cameras` 看序号，再 `run_a.bat --camera 1` |
| 中文显示成方块 | 控制台字体/编码 | 不影响传输；cmd 里先 `chcp 65001` 再运行 |

## 没有摄像头也能演

```
run_a.bat --synthetic
```

用合成动态画面（网格 + 波形 + 运动目标 + 帧号），彩排和应急都用这个，
和真摄像头走的链路完全一样。

## 其他可选参数

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| `--camera 1` | 换第 2 个摄像头 | 笔记本内置摄像头是 0，USB 摄像头常是 1 |
| `--fps 15` | 降帧率 | C 端花屏、丢帧多的时候 |
| `--quality 55` | 降 JPEG 质量 | 同上，减小单帧体积 |
| `--width 640 --height 480` | 降画幅 | 老机器带不动 960×540 时 |
