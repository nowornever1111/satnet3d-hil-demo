# 电脑 A · 发送端（真机版）

A 是**视频源**：摄像头画面 → JPEG 分包 → UDP → B 的网卡1（仿真入口）。
它到不了 C 的网段，包只能交给 B 上的 48 星仿真域转。

## 1. 唯一需要配的就是网卡地址

| 项 | 值 |
|---|---|
| 本机地址 | `192.168.100.2/24` |
| 网关 | **不配** |
| 目的地址 | `192.168.100.1:5000`（B 网卡1，脚本里已是默认值） |

Linux：

```bash
ip -br a                                   # 先看网卡名，别照抄 eth0
sudo ip addr add 192.168.100.2/24 dev <网卡名>
sudo ip link set <网卡名> up
ip -4 addr | grep 192.168.100.2            # 确认已生效
```

Windows：网卡属性 → IPv4 → 使用下面的 IP 地址 → `192.168.100.2` / `255.255.255.0`，
**网关和 DNS 都留空**。

不要加默认路由，也不要给 A 加去 `192.168.101.0/24` 的静态路由——那会让"ping 不通 C"这条关键证据失效。

## 2. 启动

```bash
bash run_a.sh                 # Linux/macOS
run_a.bat                     # Windows，双击即可
```

脚本会自动装依赖（opencv、numpy），然后以 `192.168.100.2 → 192.168.100.1:5000`
、`960x540 @25fps` 起流。

其他常用：

```bash
bash run_a.sh --list-cameras   # 摄像头不止一个时，先看序号
bash run_a.sh --camera 1       # 用第 2 个摄像头
bash run_a.sh --synthetic      # 没摄像头，合成画面跑通链路（彩排必备）
```

## 3. 开录之前的三条自检

```bash
ping -c2 192.168.100.1                        # 必须通（B 的内核应答）
ping -c2 -W1 192.168.101.2                    # 必须不通！通了说明过交换机、绕开了仿真
python3 video_sender.py --list-cameras        # 摄像头编号
```

第 2 条要在讲解时**当场演示**：A 到不了 C，画面却出现在 C 上，唯一的通路就是那 48 颗星。

## 4. 常见问题

| 现象 | 原因 | 处置 |
|---|---|---|
| `OSError: [Errno 99] Cannot assign requested address` | 本机没配 `192.168.100.2` | 回到第 1 节配地址 |
| `Network is unreachable` | B 网卡1 没起地址或网线没插 | 在 B 上 `ip -br a` 查 |
| 画面出现了但 C 上时延 0.x ms | 包被内核旁路，没过仿真 | B 上 `sysctl net.ipv4.ip_forward` 必须为 0 |
| 打不开摄像头 | 序号不对 / 被别的程序占用 | `--list-cameras`，或 `--synthetic` 兜底 |
