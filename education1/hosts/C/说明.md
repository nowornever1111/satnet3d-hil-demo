# 电脑 C · 接收端（真机版）

C 是**显示端**：从 B 的网卡2 收 UDP 分片，按帧号重组 JPEG，显示画面并统计时延。

## 1. 唯一需要配的就是网卡地址

| 项 | 值 |
|---|---|
| 本机地址 | `192.168.101.2/24` |
| 网关 | **不配** |
| 监听端口 | `5000`（脚本里已是默认值） |

Linux：

```bash
ip -br a                                   # 先看网卡名
sudo ip addr add 192.168.101.2/24 dev <网卡名>
sudo ip link set <网卡名> up
ip -4 addr | grep 192.168.101.2
```

Windows：网卡属性 → IPv4 → `192.168.101.2` / `255.255.255.0`，网关与 DNS 留空。

## 2. 启动

```bash
bash run_c.sh                # Linux/macOS
run_c.bat                    # Windows，双击即可
```

启动后窗口是黑的，这是**正常的**——要等 A 开始发、B 的仿真在跑，画面才出来。

其他常用：

```bash
bash run_c.sh --no-display   # 只统计不弹窗（后台验证链路）
```

逐帧时延会写到同目录的 `recv_latency.csv`。

## 3. 开录之前的自检

```bash
ping -c2 192.168.101.1       # 必须通（B 网卡2）
ip -4 addr | grep 192.168.101.2
```

## 4. 关于窗口上那个 delay 数字

A 和 C 是两台机器，时钟不同步，这个数字里含着两台机的钟差，
可能是 60 ms，也可能漂到几百毫秒甚至出现负数。

**演示时怎么说**：用它说明"毫秒级、逐帧连续、没有跳变"，
要报绝对时延就引用 B 上仿真日志里 gateway 的域内统计。二者不要混着讲。

## 5. 常见问题

| 现象 | 原因 | 处置 |
|---|---|---|
| 一直黑屏，B 的日志有 `sendto failed` | B 用了单机版 ini（gatewayB 绑 127.0.0.1） | B 上必须用 `semi_physical/omnetpp-semi-real.ini` |
| 一直黑屏，B 无报错 | B 网卡2 没插线 / 没起地址 | B 上 `ip -br a`、`ping 192.168.101.2` |
| `Cannot assign requested address` | 本机没配 `192.168.101.2` | 回到第 1 节 |
| 花屏、丢帧多 | 星间链路丢包（正常） | 让 A 降 `--fps 15`、`--quality 55` |
