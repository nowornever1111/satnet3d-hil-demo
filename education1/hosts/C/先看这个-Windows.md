# 电脑 C（Windows）· 三步启动

> 这台机上只做三件事：**装 Python → 配一个 IP → 双击 `run_c.bat`**。
> 起完之后窗口是黑的，这是正常的——要等 B 的仿真和 A 的发送都起来。

## 第 1 步 装 Python（只做一次）

1. 装 Python **3.9 及以上**，安装界面**务必勾选 `Add python.exe to PATH`**。
2. 装完开一个 cmd，敲 `python --version`，能出版本号就成。

## 第 2 步 配 IP

控制面板 → 网络和共享中心 → 更改适配器设置 → 右键那块网卡 → 属性
→ 双击 `Internet 协议版本 4 (TCP/IPv4)` → 使用下面的 IP 地址：

| 项 | 填什么 |
|---|---|
| IP 地址 | `192.168.101.2` |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | **留空** |
| DNS 服务器 | **留空** |

核对：cmd 里 `ipconfig`，应看到 `IPv4 地址 . . . : 192.168.101.2`。

## 第 3 步 双击 `run_c.bat`

- 第一次运行自动装 opencv / numpy；
- 窗口标题 `Receiver - decoded`，中间一行 `Receiver  frame 412  25.1 KB  delay 68 ms`；
- 一开始窗口全黑、HUD 不出现，**等 A 开始发就会跳出来**。

### 防火墙一定要放行

第一次运行会弹"Windows Defender 防火墙已阻止此应用的部分功能"，
**必须勾上"专用网络"和"公用网络"再点允许**。如果不小心点了取消：

控制面板 → Windows Defender 防火墙 → 允许应用或功能通过 → 找到 `Python`
→ 把"专用""公用"两列都勾上 → 确定。

（收端是被动监听 UDP 5000，不放行的话一个帧都进不来。）

## 开录前的自检

```
ping -n 2 192.168.101.1
```

通就说明 C 到 B 网卡2 的这段没问题。C 不需要也不应该能 ping 通 A 的 `192.168.100.2`。

## 窗口上那个 delay 数字怎么讲

A 和 C 是两台机，系统时钟不同步，这个数里含着两台机的钟差，
可能是六七十毫秒，也可能漂到几百毫秒、甚至出现负数。

**演示时的说法**：用它说明"毫秒级、逐帧连续、没有跳变"；
要报绝对时延，引用 B 上仿真日志里 gateway 的域内统计。两者不要混着讲。

接收端会把逐帧数据写进同目录的 `recv_latency.csv`，事后画图用它。

## 出问题先看这里

| 现象 | 原因 | 处置 |
|---|---|---|
| 双击黑窗口一闪而过 | 没装 Python 或没进 PATH | 重装并勾 `Add python.exe to PATH` |
| `OSError: [WinError 10049]` | 本机没有 `192.168.101.2` | 回第 2 步 |
| 一直黑屏，B 的终端有 `sendto failed` | B 用了单机版 ini（gatewayB 绑 127.0.0.1） | B 必须用 `semi_physical/omnetpp-semi-real.ini` |
| 一直黑屏，B 没报错 | B 网卡2 没插线 / 没起地址 / 防火墙挡了 | B 上 `ping 192.168.101.2`；本机确认已放行 Python |
| 画面出来但花屏、跳帧 | 星间链路丢包（正常现象） | 让 A 用 `--fps 15 --quality 55` |
| 中文显示成方块 | 控制台字体/编码 | 不影响；cmd 里先 `chcp 65001` |
